# 全球排行榜规则与实现

本文对应网页 v5.0.0 的实际实现。游戏仍在浏览器运行；全球成绩通过独立 Sites 服务写入 D1，榜单界面读取该共享数据库，空榜显示为空，连接失败不会用本地最高分或示例数据替代。

这是客户端提交的社区成绩榜。服务端登记、身份验证、范围检查与限流不能证明客户端确实完成了游戏操作；当前没有回放验证，不属于强反作弊方案。

## 九款游戏、41 个分榜

界面展示所选榜单的全球前 50 名、参与人数及当前浏览器身份的最佳成绩和全榜名次；自己的名次可以超过 50。每位玩家在每个分榜只占一个最佳成绩位置。排序依次为分数降序、服务端首次收到该最佳分数的时间升序、玩家编号升序；重复提交同分不刷新时间。服务端 API 支持查询 1–100 条，网页固定查询 50 条。

| 游戏 | 规范榜键 | 数量 | 实际分榜维度 |
| --- | --- | ---: | --- |
| 奶蛙飞不动 | `v1:flappy:{classic,endless}:{easy,normal,hard}` | 6 | 经典 / 无限、三档难度 |
| 愤怒的奶蛙 | `v1:angry:classic:{1..12}`；`v1:angry:endless` | 13 | 经典按本局起始关；无限固定从第一关开始 |
| 暴打奶蛙 | `v1:whack:{classic,endless}:{easy,normal,hard}` | 6 | 经典 / 无限、三档难度 |
| 奶蛙接不住 | `v1:catch:{classic,endless}` | 2 | 经典八波 / 无限波次 |
| 奶蛙跳一跳 | `v1:jump:{classic,endless}` | 2 | 经典 30 平台 / 无限平台 |
| 奶蛙 2048 | `v1:merge:classic:{4,6}` | 2 | 4×4 / 6×6，均允许撤销与存档续玩 |
| 奶蛙大乱斗 | `v1:fighter:{classic,endless}:{belly,speed,laugh}` | 6 | 经典 / 无限、三种角色 |
| 奶蛙幸存者 | `v1:survivor:{classic,endless}` | 2 | 经典积分 / 无限生存积分 |
| 奶蛙炸弹人 | `v1:bomber:{classic,endless}` | 2 | 从第一关出发的经典 / 无限挑战 |

`duel` 和 `training` 不生成榜键，也不登记个人积分对局；服务端使用同一规则拒绝这些榜键。处于双人或练习室时，仍可打开排行榜浏览其他玩法。

共享实现为 [前端规则](../js/leaderboard-rules.js) 和 [服务端规则](../server/lib/leaderboard-rules.js)，两份内容必须同步。这里的 `v1` 是成绩规则版本，与网页版本分开；改变计分可比性的玩法更新需要同时评估榜单版本。

```js
GAMES; // [{ id, name }]
makeBoard({ game, mode = 'classic', difficulty = 'normal',
  gridSize = 4, startLevel = 1, character = 'belly' }); // string | null
parseBoard(key); // { game, mode, ...适用维度 } | null
boardLabel(key); // 中文标签；非法键返回空字符串
getBoardChoices(game); // [{ value, label }]
validateScore(key, score, elapsedMs); // { ok: true } 或 { ok: false, code, error }
```

`validateScore` 的第三参也接受 `{ elapsedMs }`。榜键严格匹配规范形式，`01`、额外字段、尾部空白和未知版本均拒绝。`makeBoard` 忽略该游戏不使用的维度；调用方传入明确的 `mode`，不以引擎的 `training` / `multiplayer` 布尔值代替。

## 昵称、身份与公开数据

首次有效开局通过 `POST /api/players` 创建匿名玩家，再登记对局。玩家编号及身份凭据保存在当前浏览器的 `localStorage`，无账号登录或跨设备同步。仅打开排行榜浏览不要求创建身份。

昵称未保存时，结算成绩只进入本机待传队列，服务端也拒绝没有昵称的成绩提交。用户明确点击「保存昵称并提交」后，界面先保存昵称，再提交待传成绩；后续结算自动提交。仅在输入框打字不代表保存。昵称为 1–16 个可见字符，可修改；同名玩家仍是不同身份，改名会更新原身份的榜单显示。

公开榜单行只包含 `playerId`、`nickname`、`score`、`achievedAt` 和 `rank`；不包含身份凭据、棋盘、输入记录或完整游戏状态。服务端保存凭据哈希和对局记录，限流使用来源哈希，不在服务数据库保存原始 IP。清理网站数据或换浏览器会失去原身份及待传队列，不会删除已公开成绩；当前网页没有身份恢复或删除按钮。服务端提供需原身份凭据授权的删除接口。

## 对局与提交生命周期

实现位于 [客户端](../js/leaderboard-client.js)、[页面接入](../js/app.js) 和 [服务端](../server/lib/leaderboard-service.ts)。客户端在实际开局时由配置生成并保存规范榜键，后续提交不重新读取选择器。

1. 新开局、重开、选关后开始建立新的 UUID `runId`，向服务端登记 `{ board, runId }`。服务端将它与玩家、榜键、开始时间及有效期绑定；重复登记同一玩家的同一榜键 / ID 返回原始开始时间，不能更换归属或榜键。
2. 暂停 / 继续沿用原对局。2048 的继续、撤销和已登记存档恢复也沿用原 ID。仅切换游戏、改变设置或浏览榜单不提交成绩。
3. 常规游戏在最终 `onEnd` 时捕获当前对局引用和最终分数，提交 `{ runId, score }`。`onScore`、局间休息、过关动画和存档回调不是全球提交点；关卡奖励已包含在结算分数中。
4. 常规对局首个有效结算固定分数；同分重试幂等，改成其他分数返回冲突。2048 例外，允许同一 ID 的更高检查点更新。
5. 单纯关闭页面、切游戏或主动重开不补造结算。迟到的登记和提交请求仍使用原对局，不能污染新游戏或新模式。

当前协议没有独立 `checkpointId`、逐局令牌或附加战报字段：身份凭据用于鉴权，`runId` 与已接收分数用于去重。普通分数及 2048 检查点在事务中更新；数据库以 `(board, player_id)` 保存每榜个人最佳值，较低成绩和旧请求不覆盖较高纪录。

`app.js` 的 `setScore()` 仍随加分更新本地最高分。旧的 `naiwa:best:*` 数据不自动导入服务器，本地最高分和全球最佳成绩可能不同。

## 断网、重试与有效期

只有开局已成功登记的对局能进入待传队列。登记失败时游戏照常进行、成绩仅留本机；客户端不会在网络恢复后另造一个开始时间来补传离线分数。

结算上传失败会保留同一个 `runId` 和最佳待传分数。队列最多保留最近 200 个对局，刷新后可在排行榜点击「提交本榜待传成绩」；保存昵称会尝试所有待传分数，后续正常结算也会尝试同榜待传分数。网络恢复或打开弹窗本身不是后台定时重传机制。

网络错误、401、429 和服务端错误保留队列并停止本轮上传；400、404、409、410 视为永久拒绝，移除被拒绝记录并继续后面的待传项，界面不会把它们报告成已上榜。

普通对局自服务端登记起有效 **7 天**，2048 对局有效 **90 天**。检查点提交不会延长有效期。到期对局不能再提交，服务端分批清理登记记录；已进入榜单的个人最佳成绩不随对局记录过期而删除。这是对局登记有效期，不是共享规则对游戏时长设置的硬上限。

## 弹弓：始终按本局起始关分榜

`angry.start({ level })` 将分数清零，从所选关开始，自动前进到失败或第 12 关通关。页面在 `start()` 前固定榜键，所以第 1 关开局、第 6 关失败的成绩属于 `v1:angry:classic:1`；重试第 6 关创建新的 `v1:angry:classic:6` 对局。

结算时选择器可以移到结束关，不会改写已登记对局。无限模式由页面始终传入第一关，后续关卡不分榜；服务端校验规范榜键，不重放关卡过程。

历史最佳星级及结束关星级均未上传，也不当作本局累计星数。当前公共榜单只展示积分。

## 2048：续玩、撤销与刷新

两个棋盘都允许撤销一步，榜名标明“可撤销”。撤销会回退分数、步数、棋盘和达标状态，下一次生成方块可能不同；这是当前榜单允许的玩法。

- 首次达到 2048 的 `onEnd({ won: true, canContinue: true })` 是一个成绩检查点。继续冲击 4096 沿用原 ID。
- 棋盘无路的 `onEnd({ won: false })` 也提交检查点。这个 `won:false` 仅表示此时无路，不是撤销曾经达到 2048 的事实；协议只上传分数，不上传该标记。
- 无路后仍可撤销并继续。同一对局只更新较高检查点；低分、同分或旧请求不会降低已公开纪录，不会产生同一玩家的第二行。
- 游戏无路时先发出 `onSave(null)`，再发出 `onEnd`。页面保留当前内存对局，随后撤销仍能恢复原 ID 的保存。
- 新存档由页面附带 `leaderboardRun` ID，客户端另存最多 12 条已登记 2048 对局记录。刷新恢复时必须同时匹配 ID、棋盘分榜和当前浏览器身份，才继续使用该登记对局。
- 旧版或未登记的存档仍可正常游玩，但不追传分数。缺失 / 不匹配的登记信息显示“这份存档未登记全球榜”，重新开局后才能参加。已过期的登记记录可能仍在本机，但服务端会拒绝其后续提交。

2048 每局最多接收 600 次提高分数的检查点，重复或更低检查点不增加该计数。它没有按秒计算的增长限制，避免拒绝正常存档续玩；90 天登记有效期仍适用。

## 双人、训练与结算边界

大乱斗的积分是 1P 的伤害和获胜奖励。2P 获胜时 `winnerPlayer:1`、`winner:2`，`won:false` 表示 1P 败北。炸弹人的 `winner` 则为 0 起始索引，`won:true` 表示比赛分出胜负，无论谁赢。页面没有将这些字段混用成“获胜者积分”，两款本地双人模式整体排除个人积分榜。

练习室拥有无限生命与能量，也不建立排行对局。切换到经典或无限后重新开始，按实际角色生成新榜键。浏览经典榜单不会让练习成绩获得提交资格。

其余游戏的提交点为生命耗尽、挑战最终失败或经典全程通关。飞行无限模式中间掉心、弹弓中间过关、格斗局间胜利等不单独提交。幸存者经典模式需达到 180 秒且击败最终首领才通关，不是 180 秒强制停止，因此该榜标为经典积分，不以三分钟硬上限拒绝成绩。

## 服务端校验及限制

共享 `validateScore` 要求分数为非负安全整数，最高 `2 ** 40 - 1`；耗时为非负安全整数毫秒，由服务端当前时间减去数据库中的 `started_at` 得到。客户端提交耗时、额外字段、非法榜键或非整数分数都不被接收。暂停和等待上传计入服务端墙钟时间。

| 游戏 | 经典绝对分数上限 | 宽松增长上限，`t` 为服务端登记后秒数 |
| --- | ---: | --- |
| 飞行 | `2 ** 40 - 1` | `10 + 4t` |
| 打地鼠 | 20,000 | `100 + 500t` |
| 接蛙 | 10,000 | `1000 + 500t` |
| 跳跃 | 2,000 | `100 + 200t` |
| 弹弓 / 格斗 / 炸弹人 | 100,000 | `10000 + 20000t` |
| 幸存者 | `2 ** 40 - 1` | `10000 + 20000t` |
| 2048 | `2 ** 40 - 1` | 无按秒增长限制 |

无限模式使用全局整数上限，仍应用对应游戏的宽松增长校验。服务另限制请求体为 2 KiB，按来源与身份限流，校验对局归属、固定分榜和有效期；昵称以纯文本展示。以上措施处理畸形数据、明显不合理分数和重复请求，不验证每一次游戏输入。

## 仓库、部署与验证

GitHub Pages 发布内容来自静态构建白名单，仅含公开网页、JavaScript、样式和素材。`server/` 是独立 Sites 服务的源码副本，包含 API、共享规则、D1 SQL 迁移、依赖锁文件和测试，不会被复制到网页 `dist/`。修改服务器源码后，需要同步并单独发布 Sites 项目；提交 GitHub 或发布 `gh-pages` 不会更新线上数据库服务。

服务端本地安装、构建及迁移命令见 [仓库 README](../README.md) 和 [服务说明](../server/README.md)。前后端共享规则有两份，维护时同步 `js/leaderboard-rules.js` 与 `server/lib/leaderboard-rules.js`，再运行：

```sh
npm test
npm run test:leaderboard-service
npm run test:browser
```

[规则测试](../tests/leaderboard-rules.test.js)覆盖 41 个规范榜键与分数边界；[客户端测试](../tests/leaderboard-client.test.js)覆盖昵称、固定起始配置、重试、存档及并发；[服务测试](../server/tests/leaderboard-service.test.mjs)用真实 SQLite 执行服务 SQL，验证身份、排序、幂等、事务、过期与限流。[浏览器测试](../tests/leaderboard-browser.spec.js)验证弹窗、筛选、真实游戏结算接入、移动端及昵称文本展示。测试接口与正式排行榜分离，不把测试玩家填入全球榜。

独立的 [真实服务集成脚本](../scripts/test-leaderboard-live.mjs)使用两个隔离浏览器与真实 HTTP 服务，实际提交零分游戏结算，验证跨浏览器读取和刷新后的身份；结束时清理本次测试身份与成绩，清理失败也报告失败。它与使用接口替身的常规浏览器回归分开运行，支持本地和已部署服务，命令见仓库 README。
